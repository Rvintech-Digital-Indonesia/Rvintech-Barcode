# Rvintech Barcode Developer Documentation

## Overview

The root Go package is `barcode`. Encoders return an immutable `*barcode.Code`, which can be rendered repeatedly and concurrently. Encoding and rendering are deterministic for identical input and options.

## Install

```sh
go get github.com/pt-rvintech/rvintech-barcode
```

The module targets Go 1.23 or newer and has no external module dependencies.

## API

```go
func EncodeQR(text string, options Options) (*Code, error)
func EncodeCode39(text string, options Options) (*Code, error)
func EncodeCode128(text string, options Options) (*Code, error)
func LoadLogo(r io.Reader) (image.Image, error)
func (c *Code) Width() int
func (c *Code) Height() int
func (c *Code) PNG(w io.Writer) error
func (c *Code) PNGBytes() ([]byte, error)
func (c *Code) SVG(w io.Writer) error
func (c *Code) SVGBytes() ([]byte, error)
```

`Code.Width` and `Code.Height` exclude the quiet zone. Encoding functions return errors for empty or invalid input, unsupported options, low color contrast, and out-of-range QR payloads.

## Options

```go
type Options struct {
    Scale int
    QuietZone int
    Foreground color.Color
    Background color.Color
    Shape Shape
    ErrorCorrection ErrorCorrection
    Checksum bool
    Logo image.Image
}
```

Zero values choose an 8-pixel module scale, four-module QR quiet zone (ten modules for linear barcodes), black foreground, white background, and square shape. QR quiet zones must be at least four modules; Code 39 and Code 128 require at least ten. Scale must be at most 128 pixels per module and quiet zone at most 64 modules. PNG rendering is limited to 32 million pixels. Linear barcode input is limited to 512 bytes. Foreground and background must be fully opaque; foreground must be darker than background by at least 0.55 in linear luminance. This is a conservative contrast check, not a guarantee of scanner performance.

`Checksum` adds the optional modulo-43 character for Code 39. Code 128 always includes its required weighted modulo-103 symbol checksum. `Shape` accepts `ShapeSquare`, `ShapeCircle`, `ShapeRounded`, `ShapeConnected`, `ShapeBars`, or `ShapeMixed`. Circle, rounded, connected, and mixed styles alter individual QR data modules; bars use narrow vertical modules. QR function patterns remain square. Linear barcodes support square bars only. These are visual treatments and may reduce scanning margin. Use square modules when scanner compatibility is critical.

## QR Code generation

The QR implementation produces Model 2 byte-mode symbols across versions 1 through 40 and error-correction levels L, M, Q, and H. Level L is the default. It chooses the smallest version that fits. Input is UTF-8 encoded and QR byte count is based on encoded bytes. Numeric and alphanumeric mode compaction is not implemented. The largest byte-mode capacity is 2,953 bytes at level L.

```go
code, err := barcode.EncodeQR("Hello, QR", barcode.Options{})
```

QR mask selection evaluates all eight masks using the standard penalty concepts; format information and Reed–Solomon codewords are generated by the in-project encoder.

### Logo embedding

Set `Options.Logo` to an `image.Image`, or use `LoadLogo` on PNG, JPEG, or GIF input. The renderer scales the image to fit a centered area of at most 6% of the image's shorter dimension and preserves its aspect ratio. Logo requests automatically use level H and choose a version whose centered logo does not cover any finder, timing, alignment, format, or version module. The logo consumes error-correction margin even at level H. Keep logos small and verify with the scanners and print sizes you intend to support.

## Linear barcode generation

### Code 39

`EncodeCode39` accepts the standard Code 39 alphabet, normalizes lowercase input to uppercase, and adds start/stop asterisks. It returns an error for characters outside the alphabet, including the reserved start/stop asterisk. `Options.Checksum` adds the optional modulo-43 check character.

### Code 128

`EncodeCode128` currently accepts ASCII bytes. It automatically selects Code Set C for digit runs and switches to A/B when needed. It always calculates and adds the mandatory modulo-103 check symbol. FNC characters and extended Code 128 modes are not yet exposed by this API.

## Rendering and integration

PNG is encoded with Go's `image/png` package. SVG output is self-contained; if a QR logo is used, it is embedded as a PNG data URI. The quiet zone is included in both output formats. Renderers write to `io.Writer` and byte convenience methods are available for HTTP handlers, web assets, desktop applications, and document-generation pipelines.

```go
svgBytes, err := code.SVGBytes()
if err != nil { return err }
if err := os.WriteFile("code.svg", svgBytes, 0644); err != nil { return err }
```

The code object does not expose its internal matrix, and encoder state is local to each call. Do not mutate images supplied in `Options.Logo` while rendering.

## Runnable example

Run `go run ./examples/demo -format qr -text "Rvintech" -out ./barcode-output` to write both PNG and SVG. Use `-format code39` or `-format code128` for linear barcodes. The example also accepts `-shape`, `-ecc`, `-fg`, `-bg`, `-logo`, `-scale`, `-quiet`, and `-checksum` flags.
